# Frogram

Frogram — модификация [Telegram Desktop](https://github.com/telegramdesktop/tdesktop),
которая сохраняет удалённые сообщения и историю изменений сообщений.

Основана на официальном релизе **v7.0.9** (тег `v7.0.9`, коммит `a1e89e1`).
Dev-коммиты не использовались.

## Что делает модификация

### Удалённые сообщения

Когда сервер присылает уведомление об удалении, Frogram перехватывает его до
уничтожения сообщения:

* сообщение остаётся в ленте чата и помечается словом «deleted» рядом со временем;
* снимок сообщения (текст, форматирование, описание вложения, автор, даты)
  сохраняется в локальный зашифрованный архив;
* сообщения, удалённые **вами самими**, не сохраняются и исчезают как обычно.

### Изменения сообщений

Каждая правка перехватывается до применения, поэтому в архиве накапливается
полная цепочка версий: исходная, все промежуточные и текущая. Посмотреть их
можно через контекстное меню сообщения → «Edit history».

### Что не сохраняется

Сознательно исключены:

* исчезающие (ephemeral) сообщения и сообщения с таймером самоуничтожения;
* служебные сообщения, черновики и отложенные сообщения;
* собственные исходящие сообщения (настраивается);
* каналы (опционально).

## Архитектура

Новый модуль — `Telegram/SourceFiles/frogram/`:

| Файл | Назначение |
| --- | --- |
| `frogram_message_archive.h/.cpp` | Ядро: перехват удаления и правок, хранение, сериализация |
| `frogram_settings.h/.cpp` | Настройки поверх KV-хранилища `Core::Settings` |
| `frogram_edit_history_box.h/.cpp` | Окна истории правок и архива чата |

Раздел настроек — `Telegram/SourceFiles/settings/sections/settings_frogram.cpp`.

### Точки интеграции в апстрим

| Место | Файл | Что добавлено |
| --- | --- | --- |
| Удаление в каналах | `data/data_session.cpp` → `processMessagesDeleted` | Перехват перед `destroy()` |
| Удаление в чатах | `data/data_session.cpp` → `processNonChannelMessagesDeleted` | Перехват перед `destroy()` |
| Правка сообщения | `history/history_item.cpp` → `applyEdition` | Снимок предыдущей версии |
| Своё удаление | `data/data_histories.cpp` → `deleteMessages` | Пометка «удалено мной» |
| Метка в ленте | `history/view/history_view_bottom_info.*` | Флаг `Deleted` и его отрисовка |
| Контекстное меню | `history/view/history_view_context_menu.cpp` | Пункт «Edit history» |
| Хранилище | `storage/storage_account.*` | Ключ `lskFrogramArchive`, чтение/запись |
| Компонент сессии | `main/main_session.*` | `session().frogramArchive()` |

### Хранение

Архив лежит в каталоге данных аккаунта и шифруется тем же локальным ключом,
что и остальные данные Telegram Desktop (`FileWriteDescriptor` +
`EncryptedDescriptor`), — отдельной незашифрованной базы не появляется.
Запись отложена на 3 секунды после изменения, чтобы не дёргать диск.

Лимиты: 20 000 сообщений в архиве и 32 версии на сообщение; при переполнении
вытесняются самые старые записи.

## Ограничения

* **Перезапуск.** Удалённое сообщение остаётся видимым в ленте до перезапуска
  приложения: после рестарта история подгружается с сервера, где сообщения уже
  нет. Сам снимок при этом никуда не девается — он доступен в архиве.
* **Медиа.** Сохраняется текст, форматирование и текстовое описание вложения
  («Photo», «Video» и т. п.), но не сам файл: если сервер удалил медиа, оно
  останется доступным лишь пока лежит в кэше.
* **Синхронизация.** Архив локальный и не переносится между устройствами.

## Настройки

Настройки → **Frogram**:

* хранить удалённые сообщения;
* показывать удалённые сообщения в чатах;
* хранить историю правок;
* пропускать свои сообщения;
* пропускать каналы;
* очистить архив (с подтверждением).

## Сборка

Инструкции апстрима полностью применимы, см. `docs/building-win-x64.md` и
соседние файлы. Кратко для Windows:

```bash
cmake --build out --config Debug --target Telegram
```

Перед этим нужны Visual Studio 2022 с C++-тулчейном, Python 3, а также
подтянутые сабмодули и собранные зависимости (Qt, OpenSSL, FFmpeg и прочее) —
в сумме порядка 50–60 ГБ на диске.

```bash
git submodule update --init --recursive
```
